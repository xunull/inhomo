# 外发比：以「应用通道」为主体，并随行给出采样覆盖率

现有「流量」视图只按单一维度（host / App / 节点）排字节 top-N，回答的是「谁最耗带宽」。但隐私视角真正要问的是「**谁在往外送数据**」——而这个问题在按字节排序的榜单上是结构性看不见的：埋点与日志上报类的通道字节量很小，永远进不了 top-N。

## 背景事实（实测本机 7 天库，30.2 万条连接事件 / 10.7 万条流量记录）

按 `(process, host)` 聚合、按上行/下行比值排序，信号立刻浮现：

| 通道 | 上行 | 下行 | 外发比 | 流量记录数 |
|---|---|---|---|---|
| 某音乐 App → 某风控 SDK 上报端点 | 12.6 MB | 1.2 MB | 10.5 | 156 |
| 某音乐 App → 某埋点上报端点 | 15.9 MB | 5.1 MB | 3.1 | 27 |
| 浏览器 → 某视频站埋点端点 | 22.5 MB | 4.6 MB | 5.0 | 358 |
| 某 AI 客户端 → 某日志采集服务 | 9.0 MB | 1.3 MB | 6.9 | 302 |

这些通道在现有按字节排序的榜单上全部不可见——它们被某个 AI 服务 API 的 2.6 GB 淹没。

**粒度实测对比**（同一份数据，换聚合主体）：

- **只按 App**：那个音乐 App 进不了榜（前台听歌的下行把上报的上行稀释掉了）；浏览器看起来只是「正常浏览」。
- **只按 host**：那个埋点端点排得出来，但答不了「是谁在传」。
- **按 (App, host)**：上面四行全部浮出，且每行都是一句可判断的话。

**采样偏差实测**：`traffic` 表只覆盖 35.5% 的连接事件（107,285 / 301,969），被采样连接的**中位时长 60.7 秒**、仅 32 条短于 3 秒轮询间隔——即被采到的几乎全是长连接，短连接系统性缺失。但覆盖率**因通道而异**，且在高频上报型通道上并不差：某长连接端点 92.3%、某埋点端点 81.2%、某 AI 服务 API 71.5%、某 AI 站点 61.3%。

**小样本噪音实测**：「某签名工具 → 某对象存储上传端点」外发比 1598，但**只有 2 条流量记录**——纯噪音，必须有门槛挡掉。

## 决策

- **聚合主体是「应用通道」`(process, host)`，不是单一维度**。这是 CONTEXT 新增术语，也是后续新鲜度分析的同一主体。
- **独立的 `store.Exfil` 方法 + `/api/exfil` 端点**，不塞进现有 `Traffic`。理由：行的形状不同（两列主键而非一列 key）、需要跨表 JOIN 算覆盖率、有自己的门槛参数。塞进 `Traffic` 会让一个泛化聚合函数长出两套返回形状。
- **采样覆盖率随每行返回，不做隐式过滤**。`sampled`（traffic 行数）、`logged`（connections 行数）两个原始数字都给前端，比值由前端呈现。低覆盖率的行**照常返回**、由 UI 标「证据不足」置灰。
- **门槛只挡小样本，不挡低覆盖**：默认最小上行 5 MB、最小 10 条流量记录，可由查询参数覆盖。门槛是「这行数字有没有意义」的问题，覆盖率是「这行数字可不可信」的问题——前者该过滤，后者该披露。
- **落在现有 `/traffic` 页**，作为一块独立面板，不新开页面。

## 取舍

- **为什么不把外发比做成第四个 `metric`**：现有三个 metric（up/down/total）只改 `ORDER BY`，行的形状不变。外发比换了聚合主体、多了两个门槛参数、多了覆盖率两列——它不是一种排序方式，是另一种分析。共用 `metric` 参数会让 `by=host&metric=ratio` 这种无意义组合变成合法请求。
- **分母为 0 按 1 计**：`greatest(down_bytes, 1)`。纯上行通道（如上表那条下行 0 字节的签名工具通道）会得到等于上行字节数的巨大比值，但小样本门槛已经挡掉了它们；保留这个行为比引入 NULL 语义简单。
- **接受覆盖率本身也来自两个不同数据集的除法**：分子分母分别来自 `traffic` 和 `connections`，两表无稳定共享 key（见 ADR-0008），所以这是**按通道计数的近似**，不是逐连接配对。它足以回答「这条通道的字节账缺了多少」，但不能定位缺的是哪几条。
- **不做覆盖率的自动校正**：知道漏了 30% 也不去推算「真实外发比」——漏掉的短连接方向性未知，任何外推都是编数据。宁可只说「证据不足」。

## v1 不做

新鲜度分析（某应用通道首次出现）——已完成设计，见 CONTEXT 的「应用通道」术语，独立排期；外发比的时间序列（某通道的比值随时间漂移）；把外发比接进「流量拓扑」的边权；按外发比自动告警。

## 延伸

本 ADR 确立的「**结论必须随行携带它的证据基础**」这一原则，在后续新鲜度分析里会再次出现——那里对应的概念是「观测覆盖」（哪些时间区间确实在记录），形状与「采样覆盖率」完全一致：都是「这个结论建立在多少证据之上」的元信息，都选择披露而非隐藏。
